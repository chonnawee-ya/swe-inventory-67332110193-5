# Accessibility & Usability Review - Lab 04

เอกสารตรวจสอบความสามารถในการเข้าถึง (Accessibility Review) ตามมาตรฐาน **WCAG 2.1 ระดับ AA** และการตรวจสอบข้อบกพร่องที่เกิดจากการใช้ AI ช่วยออกแบบ UI

---

## 1. ตารางตรวจสอบ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่ตรวจพบและสิ่งที่ปรับปรุงแก้ไข |
| :--- | :---: | :--- |
| **1. ข้อความหลักบนพื้นขาว contrast อย่างน้อย 4.5:1** | **ผ่าน** | ใช้สีข้อความหลัก `#111827` บนพื้นหลัง `#FFFFFF` มี Contrast Ratio เท่ากับ **16.1:1** (สูงกว่าเกณฑ์ขั้นต่ำ 4.5:1 มาก) อ่านง่ายสบายตา |
| **2. ปุ่มหลัก (Primary Button) มี contrast เพียงพอ** | **ผ่าน** | ปุ่มหลักใช้พื้นหลังสีน้ำเงิน `#1E40AF` ตัวอักษรสีขาว `#FFFFFF` มี Contrast Ratio เท่ากับ **7.2:1** (ผ่านเกณฑ์ WCAG AA สำหรับ Graphical Objects และ Text) |
| **3. ทุกช่องกรอกมี label ที่มองเห็น (Visible Labels)** | **ผ่าน** | เพิ่ม `<label>` เหนือช่องกรอกทุกช่องถาวร แม้ผู้ใช้เริ่มพิมพ์ข้อความ ป้ายชื่อช่องจะไม่หายไป |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัดเจน** | **ผ่าน** | ช่องบังคับกรอกทุกช่องใส่เครื่องหมายดอกจัน `*` ต่อท้ายชื่อฟิลด์อย่างชัดเจน เช่น `ชื่อสินค้า (Product Name) *` |
| **5. Error ไม่ได้ใช้สีอย่างเดียว มีไอคอนหรือข้อความด้วย** | **ผ่าน** | ออกแบบสถานะ Error ให้มีไอคอนเครื่องหมายตกใจ `[!]` ประกอบกับข้อความสีแดงเข้ม พร้อมคำแนะนำวิธีแก้ไข เช่น *"จำนวนสินค้าต้องไม่ติดลบ โปรดระบุจำนวนเต็มตั้งแต่ 0 ขึ้นไป"* ผู้ใช้ที่ตาบอดสีสามารถเข้าใจได้ทันที |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | จัดเรียงโครงสร้าง DOM ตามลำดับการอ่าน: ชนิดสินค้า ➔ รหัสสินค้า ➔ ชื่อสินค้า ➔ จำนวน ➔ ราคา ➔ ปุ่มยกเลิก ➔ ปุ่มบันทึก |
| **7. ปุ่มมีชื่อบอกหน้าที่ชัดเจน ไม่ใช่แค่ OK หรือ กากบาท** | **ผ่าน** | ใช้ชื่อปุ่มบ่งบอกการกระทำชัดเจน เช่น `บันทึกข้อมูล (Save)` และ `ยกเลิก (Cancel)` แทนการใช้คำสั้นกำกวม |

## 2. จุดที่ AI ออกแบบพลาด และการแก้ไขด้วยมนุษย์ (อย่างน้อย 2 จุดตามเกณฑ์ Rubric)

### จุดผิดพลาดที่ 1: AI ใช้ Placeholder แทน Label และใช้สีเทาอ่อนที่ Contrast ไม่ผ่าน
* **สิ่งที่ AI สร้างให้ในรอบแรก:**
  AI ร่างฟอร์มโดยไม่มีข้อความ Label ด้านบน แต่ใส่ข้อความตัวอย่างไว้ข้างในช่องกรอก (Placeholder) เช่น `[ ป้อนชื่อสินค้า... ]` และใช้สีเทาจาง `#9CA3AF` บนพื้นขาว
* **ปัญหาด้าน Accessibility & Usability:**
  1. Contrast Ratio ของสี `#9CA3AF` บนพื้นขาวอยู่ที่เพียง **2.8:1** (ตกเกณฑ์ WCAG AA ที่กำหนดขั้นต่ำ 4.5:1) ทำให้ผู้ใช้สายตาเลือนรางอ่านไม่ออก
  2. เมื่อผู้ใช้คลิกพิมพ์ตัวอักษรแรก ข้อความ placeholder จะหายไปทันที ทำให้พนักงานคลังสินค้าสับสนว่ากำลังพิมพ์ช่องไหนอยู่
* **สิ่งที่มนุษย์ปรับปรุงแก้ไข:**
  ยกเลิกการพึ่งพา Placeholder แล้วเพิ่มป้ายชื่อช่อง (Visible Label) ชัดเจนค้างไว้ด้านบนด้วยสี `#111827` (Contrast **16.1:1**) พร้อมกำหนด `for` attribute เชื่อมกับ `id` ของ input เพื่อรองรับ Screen Reader

---

### จุดผิดพลาดที่ 2: AI แจ้งเตือน Error โดยใช้สีแดงเพียงอย่างเดียว และข้อความไม่บอกวิธีแก้
* **สิ่งที่ AI สร้างให้ในรอบแรก:**
  เมื่อเกิดข้อผิดพลาดในการกรอกจำนวนติดลบ AI เปลี่ยนเพียงสีกรอบของช่องกรอกเป็นสีแดง และแสดงข้อความสั้น ๆ ด้านล่างว่า `Error: Invalid input`
* **ปัญหาด้าน Accessibility & Usability:**
  1. ขัดต่อหลักเกณฑ์ WCAG 1.4.1 (Use of Color) ผู้ใช้ที่มีภาวะตาบอดสีแดง-เขียว (Protanopia/Deuteranopia) จะมองไม่เห็นความต่างของสีกรอบ
  2. ข้อความ `Invalid input` ไม่ได้บอกว่าผิดอะไร และไม่ได้แนะนำผู้ใช้ว่าต้องแก้ไขอย่างไร (Actionable Guidance)
* **สิ่งที่มนุษย์ปรับปรุงแก้ไข:**
  เพิ่มไอคอนเครื่องหมายตกใจ `[!]` หรือ SVG Alert Icon ข้างข้อความ และเปลี่ยนข้อความให้ระบุสาเหตุพร้อมวิธีแก้ชัดเจน: `"[!] จำนวนสินค้าต้องไม่ติดลบ โปรดระบุจำนวนเต็มตั้งแต่ 0 ขึ้นไป"`

---

### จุดผิดพลาดที่ 3 (จุดเสริม): AI ออกแบบระบบสำหรับสินค้าชนิดเดียว ไม่ครอบคลุมสินค้าดิจิทัล
* **สิ่งที่ AI สร้างให้ในรอบแรก:**
  AI ออกแบบฟอร์มบังคับกรอกจำนวนสต็อก (Quantity) โดยถือว่าสินค้าทุกชิ้นต้องนับจำนวนสต็อกในโกดัง
* **ปัญหาตาม Requirement:**
  โจทย์กำหนดให้ระบบรองรับ 2 ชนิด คือสินค้าที่จับต้องได้ และสินค้าดิจิทัล (ไฟล์/License) ซึ่งสินค้าดิจิทัลขายได้ไม่จำกัดและต้องการลิงก์ดาวน์โหลด
* **สิ่งที่มนุษย์ปรับปรุงแก้ไข:**
  เพิ่มตัวเลือก Radio Button เลือกประเภทสินค้า หากเลือกสินค้าดิจิทัล ระบบจะล็อกช่องจำนวนเป็น "ไม่จำกัด" และเปิดช่องกรอก "ลิงก์ดาวน์โหลดไฟล์ (Download URL)" ขึ้นมาแทน
